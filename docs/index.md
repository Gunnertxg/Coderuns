# 设计思路与制作过程日志（团队视角，10.6 – 10.18）


> 本文记录这辆小车从设计构想到实物制作的全过程，整车目标始终只有一个：**做一辆能拾取并携带方块的小车**


## 一、整体设计思路：这辆车是怎么"想"出来的

设计不是一次定死的，是顺着"目标 → 难点 → 妥协"一步步长出来的。我们把这条思路单独拎出来，方便看懂每个结构为什么是现在这个样子。

### 1. 先解决"能跑"，再解决"能抓"

目标是一辆能拾取并携带方块的车。我们判断，移动是前提，所以第一步就是让车能动起来。
这部分相对成熟，**直接采购现成底盘 + TT 马达 + 麦克纳姆轮**即可（麦轮能全向移动，对后面要绕到方块旁边很有用）。

### 2. 要"抓"——想到机械臂

车能跑了，下一步是拾取方块。能完成"伸过去、抓住、收回"这种动作的，最自然的就是**机械臂**。于是机械臂进入了方案。

### 3. 要"带"——想到车斗

抓起来之后得有个地方放。一开始想的是"抓起来抱在机械臂上到处跑"，但这既占着机械臂、又容易掉，不如**专门做一个车斗来装方块**。携带问题由此解决。

### 4. 车斗为什么选 3D 打印

现成的小盒子尺寸往往和我们实际要装的方块对不上——要么太大占地方，要么卡不住方块。我们判断，与其反复找"差不多的盒子"，不如**自己 3D 打印一个严丝合缝的车斗**。这也顺带让我们去学 Fusion（建模）、3D 打印流程和工程塑料的通识。

### 5. 一个现实空间问题：DRV8833 放不下

车上的面包板是 **400 孔的小板**，两块 DRV8833 驱动一插，剩下的地方根本不够布线。
权衡之后，我们决定**不把 DRV8833 插在面包板上，而是直接贴在底盘金属底板上**，只把核心的控制模块（面包板、蓝牙接收器）留在后面。

### 6. 金属底板会短路——缠电工胶

底板是金属材质，驱动芯片贴上去万一碰到金属就会短路。
解决办法朴实但有效：**把整块底板缠一层电工胶做绝缘**。这一步后来还救了我们——缠胶是在底盘组装好又拆开之后才做的（见 10.12），顺序很关键。

### 7. 布局的一次重要反转：车斗和机械臂谁在前

这是我们设计上最值得记的一笔。

 **最初方案**：机械臂放最前面，车斗放后面。直觉上"手在最前好去够东西"。
 **问题**：机械臂要把抓到的方块放到**后面**的车斗里，意味着它得在水平面大致 360° 旋转、绕过车体才能送回去，结构和控制都很难做。
**改后方案**：**车斗放最前面，机械臂放中间（偏后）**。这样一来，机械臂抓到方块后，只要**往回缩**就能把方块送进前方的车斗，动作简单又可靠。

### 8. 一个主动放弃的"好点子"

我们曾想过给车斗加一个盖子，并和机械臂做**联动**：机械臂把方块放进去后盖子自动合上，对手就没法从我们车斗里抢方块。想法很妙，但一细想，**这套联动的机械结构太复杂**，以当前人力和时间不划算，于是**主动放弃**，先把核心功能做稳。

### 9. 最终布局（定稿）

经过上面这些取舍，整车从前到后的布局定为：

[ 车斗（最前）] → [ 机械臂（中间）] → [ 控制模块：面包板 + 蓝牙接收器 + DRV8833（最后）]




## 二、底盘运动（从物资采购到第 1 次联调，同期机械臂组装加调试，10.6 – 10.15）

底盘运动是整个项目最早启动、也最基础的功能：让车能按手柄全向移动。
下面按时间记录它的开发过程。

### 10.6 目标确定，分头采购

今天把整车目标敲定：**能拾取并携带方块的小车**。全队集体研讨比赛规则，确定机器人核心任务为收集场地内30×30×30mm能量单元与能量核心方块。底盘选用官方四轮金属底盘+TT电机+麦轮，电源采用双节18650电池。

物资分头采购，该买的都买了：底盘、TT 马达、麦克纳姆轮，以及 STM32 开发板、驱动、接收器等。

在采购间隙，先去了解要用什么软件工具链——对比了 **STM32CubeMX（图形化配置引脚和时钟）、STM32CubeIDE（写代码+调试一体）、Keil、CLion**。最终以 CubeMX + CubeIDE 为主组合来用，其余作为了解。


收集机构初期方案：**推土板结构**，依靠车体向前运动将方块推入后方储物仓。
结构材料初期规划：机架、推土板、储物仓全部使用PLA材料3D打印，在Fusion360完成建模后提交打印。

讨论中已暴露隐患：推土结构对位精度要求高，方块容易被推飞；PLA材料抗冲击弱，比赛冲撞和跌落测试存在断裂风险。但当日仍按推土方案推进建模。

任务分配：机械组开始Fusion360建模，电控组梳理STM32、PS2手柄、电机驱动接线。



### 10.7 – 10.11 等物资的窗口期：两路工作并行

完成推土机构+储物仓三维模型。团队内部评审发现两处重大问题：
1. 场地存在坡道、高台，机器人倾斜时推土结构极易将方块挤飞，无法稳定留存；且只能向前收集，无法拾取侧面、后方方块，战术灵活性差。
2. 3D打印PLA部件厚度有限，按检录150‑200mm跌落测试标准，推土挡板经撞击、跌落容易开裂；打印周期长，修改结构需重新打印，迭代效率低。

对比两套收集方案：

|方案|优点|缺点|
| ---- | ---- | ---- |
|推土结构|舵机用量少，控制简单|拾取角度受限，易推飞方块，抗冲击差|
|多自由度机械臂|多角度抓取地面、高台、悬挂方块，适配复杂地形|需多个舵机，装配难度上升|

> **关键决策一：放弃推土收集机构，改为舵机驱动小型机械臂夹爪机构**，可拾取地面方块，同时够取物资架悬挂的能量核心。
> **关键决策二：结构材料由全3D打印改为铝板为主，3D打印仅用于小连接件、夹爪内衬。**

原因：PLA打印件承受舵机反复扭转、赛场碰撞，易出现层间剥离断裂；铝板抗冲击、抗扭性能优于PLA，可手工裁剪折弯，修改迭代速度远快于重新打印。


此时物资还没到齐，但时间不能浪费，两路工作同时推进：
**电控**
- 趁这段时间把代码和软件学起来，用 **LED 闪烁做"试手"**——先验证开发环境、下载、点灯这套流程走得通，后面才敢往上叠复杂功能。
- 先到的一部分物资开始拼装**底盘**（把 TT 马达和麦轮固定到底盘上），同时开始学 **Fusion** 建模。

> 注意：这个时候底盘自带的膜被撕掉，**还没缠电工胶**——缠胶是后面 10.12 才做的事，顺序很重要。

**机械**
机械臂设计参数：
- 自由度：2个转动关节（大臂+小臂）+ 1个夹爪开合，共3个舵机
- 大关节驱动：MG995金属齿舵机（扭矩大，承受臂节负载）
- 末端夹爪：SG90舵机（轻量，满足30mm方块夹持）
- 主体材料：1.5mm铝板折弯
- 夹爪内衬：3D打印PLA，增加摩擦力

重点校核两项规则约束：
1. 初始整机尺寸≤290×195×210mm；机构完全展开≤445×400×450mm，满足球体变形约束。
2. 估算整机重量，铝板选用1.5mm薄板，控制机械臂组件重量，防止超重。

设计中发现并解决的问题：
铝板开孔位置若设计不合理会干涉舵机输出轴。修改模型，预留舵机安装避让空间。

对比：全3D打印该机械臂预估打印时间12小时以上，一旦装配发现干涉需重新打印；铝板可现场修改开孔，调试效率更高。

装配半成品机械臂，空载通电测试舵机转动。
**发现新问题：**铝板刚性大，舵机大力转动时若限位未做好，容易发生硬顶，有烧坏舵机风险。
**解决办法：**软件增加舵机角度限位，硬件增加机械挡块，限制机械臂运动范围。

### 10.12 一次关键会议：把布局定死 + 底盘返工 + 代码开工

今天开了一次会把前面"设计思路"里那些想法落了地：

- **会议结论**：正式确立 **车斗在前、机械臂在中、控制模块在后** 的布局（也就是上面第 7、9 点的方案）。
- **底盘返工**：为了缠电工胶，先把刚装好的底盘**拆开**，给金属底板整体缠一层绝缘胶，再**重新组装**。顺带开始学**机架与结构设计**，以及为车斗做准备的 **3D 打印工具与工程塑料通识**。
- **代码开工**：开始写**底盘运动代码**——也就是手柄数据怎么进来、怎么解算成四个轮子的速度。

### 10.13 – 10.14 并行推进

- 继续写底盘运动代码，重点在 PS2 手柄与蓝牙接收器之间的通信、以及芯片收到数据后如何解算、再驱动轮子。
- 用车斗的 3D 模型推进打印准备，把"现成盒子不合适 → 自己打印"的想法变成实物。

### 10.15 第一次联调：先动起来，再谈智能

今天第一次把各部分合到一块测，分了两步走，思路很稳：

1. **先测硬件通路**：逐个测试四个 TT 马达，确认每个都能转——先把"电机—驱动—板子"这条线证明是通的（这一步详见"电机运动"一节）。
2. **再测整条控制链**：跑**底盘运动控制代码**，验证完整的 **"PS2 手柄 → 蓝牙接收器通信 → 芯片解算 → 轮子动作"** 闭环。

## 三、电机运动（联调当天，逐马达测试）

电机运动聚焦在最朴素也最不可跳过的一步：确认每个马达本身都能正常转。

### 10.15 联调当天，四个 TT 马达逐个测试

第 1 次联调一开始，并没有急着跑整车控制，而是**先单独测试每一个 TT 马达**：依次驱动左前、右前、左后、右后四个轮子，确认每个都能转。

这一步的意义在于：它把"电机 — 驱动 — 开发板"这一最底层的硬件通路先证明是通的。只有先确认"每个轮子单独都能动"，后面再去查"为什么整车不动"时，才能放心地把问题锁定在通信或解算，而不是又回头怀疑马达接线。它是底盘运动能跑起来的前提，也是所有更复杂动作的地基。

## 四、舵机运动（10.16）

舵机运动对应机械臂的关节控制：用舵机的角度变化，让机械臂能伸出去够方块、再收回来。

针对前几日抓取测试中方块偶发脱落的问题，进行第三轮优化：
1. 调整夹爪开合角度，增大夹持行程；
2. 更换更厚的橡胶防滑垫片，进一步增加摩擦力；
3. 优化舵机转动速度曲线，夹爪闭合时减速，避免冲击导致方块弹出；
4. 反复多次抓取模拟方块测试，记录成功率，逐步提升至稳定水平。

### 10.16 机械臂组装 + 舵机控制代码

底盘联调成功后，开始补齐拾取能力：

- 组装**机械臂**实体，装到车的中后部
- 写**机械臂控制代码**（舵机的角度控制、抓取/释放动作），让手柄能驱动机械臂去够方块。

进行方块抓取测试：机械臂可将地面静止方块由非携带状态切换到携带状态，完成【方块携带（单一）】指标演示。

继续测试连续抓取，尝试抓取第二个方块。
**发现问题：夹爪夹持力不足，方块容易脱落。**
分析原因：铝板夹爪表面光滑，摩擦力不足。
**解决方案：在夹爪内侧粘贴橡胶防滑垫片，增加摩擦力。**

## 五、方块携带（机械臂组装到第 2 次联调，10.16 – 10.18）

方块携带是整车的最终目标：把"移动 + 抓取 + 入斗"整合成一条完整闭环——开到方块旁边、机械臂抓起来、缩回放进前方车斗。这个功能跨越了机械臂组装到第 2 次联调，时间上与舵机运动有重叠。

### 10.16 机械臂就位，携带闭环的"手"和"兜"都齐了

机械臂组装并写好转控代码（详见"舵机运动"一节）的同时，车斗（此前已通过 3D 打印准备好）一直处于车身最前。至此，"能抓的手"（机械臂）和"能装的兜"（车斗）都已就位，只差把它们联动起来验证。

### 10.17 收尾与复盘

把目前所有工作串起来看，整车已经从"一堆零件"变成"能走能抓的平台"：

```
采购底盘/马达/麦轮（能跑）
   → 设计机械臂（能抓）
   → 设计车斗+3D打印（能带）
   → DRV贴底板+缠电工胶（空间与绝缘）
   → 布局定稿（车斗前/机械臂中/控制后）
   → 10.15 联调跑通移动
   → 10.16 机械臂上线
```

**这趟最有价值的几条经验：**

1. **先并行、后合拢。** 物资没到时各学各的（软件工具、建模），到齐后再合到同一辆车，互不阻塞。
2. **联调要"先通路、再闭环"。** 先确认每个马达能转，再跑完整控制链，定位问题快得多。
3. **设计要尊重"难做"这件事。** 机械臂 360° 送料太难，我们就改成"车斗前移、机械臂回缩"，用布局换简单——这是用巧劲，不是将就。
4. **敢于放弃好但贵的功能。** 车斗联动盖子很酷，但机械结构太复杂，主动砍掉，先把核心做稳。
5. **绝缘和顺序不能省。** 金属底板缠电工胶、且必须在组装前做好，这类"不起眼但会短路"的细节，回头补比一开始就做更费事。

### 10.18 第 2 次联调：把"移动 + 抓取 + 入斗"串成闭环

第 2 次联调的目标，是把前面分别验证过的功能整合成整车的最终能力。重点测试：

- 车按手柄开到方块旁边（**底盘运动**）；
- 机械臂伸出去抓住方块（**舵机运动**）；
- 机械臂**往回缩**，把方块送进**前方车斗**（**方块携带**）。

这一步走通，意味着"拾取并携带方块"的整车目标达成——车不再只是"能走"或"能抓"，而是真正完成了从目标到收纳的一整条任务链。方块携带功能至此闭环。

> 日志完。后续方向：机械臂抓取与车斗投放的联调打磨、整体走位策略、以及更稳的接线方式。
